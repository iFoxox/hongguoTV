# 果映 TV 原生客户端

工程：Kotlin + Android View + Media3。最低 Android 6.0 / API 23；compileSdk、targetSdk 为 36。安装标识 `io.github.tsukiyo_zero.guoyingtv`，与旧原生包 `com.hongguotv.nativeapp`、React Native 包 `com.hongguotv` 的数据独立。Kotlin namespace 暂保留旧命名，Manifest 使用完整 Activity 类名，真正安装标识以 APK 的 applicationId 为准。

此 fork 的正式版本为果映 TV 0.1.13 / versionCode 54，使用独立签名和包名 `io.github.tsukiyo_zero.guoyingtv`。不能覆盖安装原签名或调试签名版本；卸载旧版可能清除本机数据与登录态。后续更新须保留此 fork 的签名，并支持 Android 6 v1 签名。

桌面图标与应用内标识采用 C3 蓝紫渐变果实银幕图，TV 启动器提供「果映 TV」横幅。主图与生成提示词见 [品牌资源](artwork/README.md)；多密度桌面图标覆盖 Android 6+，本轮使用完整位图，不依赖透明拆层或自适应前景。

功能介绍见 [项目主页](../README.md)，工作约定见 [开发流程](../CONTRIBUTING.md)。

## 首页刷剧

播放前先完成一次匿名设备注册，首页与正式播放共用平台返回的设备 ID、安装 ID 和设备 Cookie；同一应用进程内复用，不再随机生成未注册 ID，也不因播放失败轮换身份。注册不登录账号、不发送短信，身份仅保留在内存，不进入本机历史或备份。取消页面请求仍可取消注册，注册失败后不使用随机 ID 继续请求播放，并显示「播放设备注册失败」；后续播放操作可重新尝试尚未成功的注册。新进程首次播放需要完成注册，平台不可达时仍可能失败。

首页与正式播放共用播放信息读取：空白响应最多读取三次，间隔 700 / 1500 毫秒；瞬时连接故障或 HTTP 500/502/503/504 仍只重试一次。每次读取更新请求时间戳，不更换设备身份；切换页面或取消任务仍会取消请求。有效业务错误码、其他 HTTP 错误和响应格式变化不触发这次内部重试；持续失败时仍保留手动重试和原有正式播放恢复机制，不承诺固定恢复时间。正式播放的错误原因在重试倒计时期间仍显示，区分空响应、HTTP 错误、超时和视频分段中断。

首页仍试播第一集，不把试播当作正式观看记录。「观看全集」进入详情后，续播按钮比较本机和当前账号已读取的云端历史，使用更新时间较新的记录（同时间优先本机）；无记录时从第一集开始。云端范围仍限当前账号最近已读取的 50 部，不保证未加载的云端记录可用。

账户历史直接播放时使用该条云端进度；云端分集 ID 无法匹配官网分集列表时，按有效云端集号定位，并保留时间位置。ID 可匹配时优先采用 ID，避免分集顺序变化造成错集；集号无效时不强行套用时间。本机历史继续使用本机 checkpoint，云端记录不预先写入本机历史。

切回本次已浏览的推荐、漫剧、真人剧时恢复该来源的列表、分页和选中作品，试播从头开始；「换一批」仍请求新批次。账号变化清空三类来源状态。另有按登录身份隔离的 10 分钟首屏元数据缓存，每来源最多 30 部，仅保存卡片与经过详情核验的首集 ID/总集数；不保存播放 URL、服务端游标或凭据。缓存命中先试播缓存作品，后续分页以新的服务端会话获取并去重，过期或损坏时直接联网。

播放模型若包含完整可用的 video_meta、encrypt_info 与媒体地址，直接选流和派生内容密钥；缺少可用项时保留原备用接口。首页先在一个 256 KiB 范围请求中消费 32 KiB，再按实际索引大小继续读取，索引超过范围时补取；正式全集播放仍采用原首段大小。首次进入、冷缓存和缺少可靠首集标识的分类仍有必要的联网请求。

首页推荐、漫剧与真人剧均试播第一集。保留下一部至第三部的播放地址与完整索引缓存（先消费 32 KiB，再补齐完整索引，不等待整个 256 KiB 范围响应）；当前视频正在播放且缓冲达到 1.5 秒后，启动下一部的预加载。完成地址和索引解析后立即交给 Media3，无需等额外固定 1 MiB 下载；Media3 提前解析轨道并将下一部约 1.5 秒的媒体样本放入播放器缓冲，后两部只提前选择轨道；播放器预加载总缓冲目标为 4 MiB。沿用一个播放实例，不为每部作品建立独立解码器。

上下换剧时复用缓存；若目标作品仍在预加载，则接续该任务，失败后退回前台加载，避免取消后重复解析与下载。同一 HTTP 分段中的视频数据边到达边交给播放器，不等待整个 512 KiB 分段完成。切换类型、换批、离开页面或退出仍取消过期任务并清理资源。

本轮参考本地官方 App 6.5.5.32 中可识别的 TTVideoEngine、DataLoaderHelper 和短视频预加载组件，采用独立实现；静态分析不能确认官方实际启用的策略或参数。Media3 接入依据 [Android 官方预加载文档](https://developer.android.com/media/media3/exoplayer/preloading-media/preloadmanager)。首页加载优化已经用户验收并纳入正式 0.1.11。没有与官方 App 进行设备测速对比，不承诺固定首帧耗时；缓存未命中时仍需要必要的推荐、播放地址和视频索引请求。

日志只记录 `Home recommendations`、`Home category`、`Home detail`、`Home starter-cache hit`、`Home play-address`、`Home promoted in-flight preload` 与 `Home first-frame` 等阶段信息，不打印播放地址或账户信息。`first-frame` 从交给播放器开始计时，不包含此前推荐及地址请求耗时。

## 正式播放与下一集

正式播放一次请求当前集和后两集的播放模型，仅将服务端按分集 ID 返回的后续模型保留在内存，最多 6 条、60 秒过期，领取即移除。连续切集或预加载可省去这次模型请求，缺失或过期仍单独获取；重试同一集不会反复使用同一个旧地址。不额外下载后两集的完整视频，不持久化媒体地址或密钥。批量接口已作匿名实测，实际设备效果待验收。

自动连播按倍速折算后剩余 30 秒内准备下一集，仍要求当前播放稳定、有足够缓冲、前台且非计费网络。播放地址复用当前 Repository 的设备标识与匿名会话；视频传输保持独立的连接池和请求调度器，继承正常播放的超时，取消预加载不会取消当前集的请求。

下一集先读取 32 KiB，并按实际 MP4 索引长度继续补齐；索引可用后立即加入同一播放器队列，由播放器继续缓冲，不等待额外固定 2 MiB。手动或自动切集时，若对应准备任务尚未结束，则在后台接续该任务，不先取消重来；准备失败时仍可回退到正常获取流程。退出、切换其他集或取消播放会取消接管任务并关闭迟到资源。已经入队的下一集保持原有同播放器接续、进度保存与定时停止规则；不承诺所有网络、格式和电视均无缝切集。

## 遥控器搜索

找剧页保留原组合筛选，点击「屏幕键盘」进入独立搜索工作区；提交关键词后也进入该布局。左侧为 6 列 A–Z/0–9 键盘，提供删除、清空、搜索、系统中文输入、手机输入和返回分类；中间为服务端联想及最多 8 条最近搜索，右侧为连续分页海报结果。结果按显示宽度使用 2/3/4 列，窄屏时缩小侧栏，键盘区可纵向滚动，不挤占组合筛选。触屏设备（以及宽度小于 520dp 的窄窗口）改为单列布局：顶部输入框直接调用系统输入法，下面依次是清空/返回分类、联想词和结果列表，不再显示字母键盘、手机输入与屏幕键盘入口，提交或离开页面时收起输入法。

字母按键输入小写字符，插入/删除遵守光标选区；删除按 Unicode 字符处理，不拆开代理对。输入最多 80 字，联想仍延迟 350ms 并取消旧请求，选择候选词或历史后明确搜索；不自动把字母当作保证可匹配的拼音首字母。左右可在键盘、候选与结果之间移动，结果首列向左返回词条区；返回退出搜索回到组合筛选。中文输入调用系统输入法，手机输入仍需可互通局域网。布局与控件回归覆盖 API 23/26，遥控器手感需用户验收。

## 连续浏览

找剧分类接近底部时按服务端返回的偏移和会话游标继续加载，关键词搜索按服务端页码继续加载，结果均去重追加。分类和搜索遇到连接超时、连接中断、域名解析失败或 HTTP 500/502/503/504 时，等待片刻后自动重试同一请求一次；其他 HTTP 错误或响应格式异常不自动重试。仍失败时保留当前列表，底部显示错误类型并可手动重试。搜索返回分类、从详情返回列表时恢复选中作品。排行榜使用六列海报网格（手机竖屏 3 列、平板 4–6 列，按宽度自适应），沿用完整榜单和全榜题材筛选，卡片标注原榜名次与可用热度，连续浏览不改变原始名次。榜单请求在内存中携带站点重定向下发的会话 Cookie（不落盘），读取使用收紧的超时并在瞬时失败时自动重试一次。四个榜单各自独立并行加载、互不取消：会话内 10 分钟 TTL 内切换直接展示缓存零请求，过期后展示旧榜单的同时后台静默续期，用户点刷新才强制重拉；切换榜单永不进入模态等待。找剧分类页移除常驻加载／回顶按钮，接近底部自动加载，失败才显示重试；分类页按返回回顶并聚焦「找剧」，再次返回按原导航规则离开。搜索结果与排行榜保留各自原有返回和回顶操作，长按确认或菜单键管理作品。

输入停顿 350 毫秒后请求官网公开联想接口，最多显示 8 个候选；服务端可将部分拼音输入匹配为中文剧名。选中候选后按该中文词搜索，不自动打开详情；直接搜索、搜索历史与手机输入仍可使用。联想请求使用独立可取消任务，不中断当前结果分页；输入变化、离开页面或切到后台时取消过期任务，失败不阻止直接搜索。不承诺任意拼音、首字母或错别字都能匹配。

分类使用 App 分类接口的真实分组：类型（全部、真人剧、漫剧、AI 剧）、主题、设定、背景、推荐排序、受众、上新时间，以及服务端提供时的作品状态。每组单选，不同组的条件组合提交到服务端，不是只筛选已加载作品；每行「全部」清除本组条件，受众「女频」的值为 `0`，与「全部」区分。切换内容类型会清除旧类型的条件并重新获取分组，重置会回到全部类型、全部条件。

遥控器左右选择同组条件，上下切换分组；较小屏幕可上下滚动筛选区。进入海报列表保持筛选展开状态，可手动收起；列表首行向上可到筛选控制按钮；搜索或详情返回后保留组合条件、列表、选中作品及筛选行滚动位置；选中高亮始终依据实际筛选条件重绘，横向超出可视区域的选中项会恢复到可见范围。分类仍最多加载 100 批，未返回的分组或选项不自行补造。可用高度不足时海报缩小，标题改为单行，必要时隐藏副信息以保留列表空间；完整作品信息仍可进入详情查看。旧网页分类入口继续保留给首页兼容路径及 Mac 客户端，本轮未改变它们的行为。

界面使用 Android 系统 GridView 回收离屏卡片，搜索最多 100 页、分类最多 100 批；切换分类、题材或关键词会重新从首批读取。账户收藏、历史和预约的读取范围不变。遥控器手感仍需用户在电视上验收。

## 界面主题与导航

TV 浏览页上下安全边距为 8dp，不再各占屏高 5%；手机页面留白不变。首页左下「更多作品／继续观看」显式使用当前主题正文色，避免浅色主题下文字与背景接近而看似空白。文字对比度回归覆盖浅／深色和 API 23／26；实际电视视觉仍以用户验收为准。

TV 的「观看历史」是独立一级入口，位于首页后的第二项；所有屏宽的顶栏均按「首页、观看历史、找剧、排行榜、收藏、账户预约、设置」排列。点击直接进入本机／账户历史页，保留既有历史记录和来源选择；左右按显示顺序移动，向下进入内容。

TV 按选定的 B「海报墙＋固定预览」方案重组：七项导航统一置顶，首页左侧三列海报，右侧唯一试播播放器、标题、题材、简介与常驻操作。移动海报焦点不切换播放索引、不解析另一条播放流；浏览其他作品时暂停旧试播，并用所选封面遮住旧画面，确认才切到该作品第一集。初次进入仍沿用首部作品试播，已有邻近预加载策略保留。海报用 GridView 回收，按可用高度显示一行或两行并纵向浏览；「更多作品」追加当前来源，不重置已有试播。右边界向右进入试播操作、首行向上回到来源栏；预览区按返回先回海报，再按原导航规则返回顶栏。浏览作品标识按来源保存，详情返回可恢复海报位置。

有本机记录时，海报墙下方提供「继续观看」入口，以列表选择记录后进入详情续播；无记录不显示入口。完整本机／账户历史仍从顶部第二项进入。手机与平板继续使用四栏底部导航和原有首页布局。界面提供浅色与深色两套主题，默认浅色；在「设置 → 外观」切换并保存在本机。橙色描边表示焦点，栏目选中有独立底色。剧集详情页保留封面渐隐背景（API 23 不依赖模糊）。本轮 TV 布局尚待用户实机验收，不改变版本号、包名与签名策略。

TV 详情页选集下方的「相关作品」保留官网完整返回顺序与季数、同 IP、待上线标记，并标示不可重复跳转的当前作品。与手机复用季数定位规则：当前第 9 季且官方季标记可对应时，初始横向位置及遥控器进入焦点在第 8 季附近；无法可靠对应则从开头展示，不把同 IP 当作同系列。左右连续浏览，边界停留当前卡片，上键进入刷新，再向上回选集；下键回到刚浏览的卡片，刷新和失败重试后保留浏览目标。异步加载不抢走播放／选集焦点。已上线作品继续进入原有详情和续播流程，待上线作品沿用账号预约。M25 为手机／TV 通用本地测试包，实机遥控器手感及账号预约结果仍待用户验收。

TV 全屏播放按上键或菜单键展开操作区，在「选集」旁选择「相关作品」，会保存观看进度、退出播放并直接定位当前剧集详情中的相关作品区域。加载中聚焦刷新，成功后落在上一季附近，失败可直接重试。保留详情页原入口、跳转、预约及续播逻辑；实际 TV 遥控器操作仍需用户安装验收。

TV 详情和播放选集统一每组 120 集（1—120、121—240……），最后一组只显示实际集数。播放选集弹窗在屏幕中央显示，左侧为独立纵向滚动的分组标签，上下移动焦点即切换右侧列表；向右或确认进入集数，行首按左回到当前分组标签，再向右回刚浏览的集数。不再显示上一组／下一组按钮。右侧使用紧凑网格，数字字号 14sp、最小高度 38dp，「当前／上次／已看」另起一行，为四位集数保留宽度；大字体或窄窗口按文字实测宽度减少列数，必要时纵向滚动。打开时聚焦当前集、左侧自动显示所属分组；切组和跳转定位不改变播放，确认集数才播放。详情选集同步使用 120 集分组和紧凑行高，遥控器可到达末行与相关作品。手机仍为每组 20 集、底部面板和至少 48dp 点击区域。API 23／26 回归覆盖居中、纵向分组、120／121 边界、末组、四位数字、大字体及焦点往返；实际电视操作待用户安装验收。

## 手机与平板（触屏）

启动时结合电视模式、电视硬件标志、触摸屏能力与系统触摸配置判断界面，兼容漏报触摸屏硬件标志的手机。「设置 → 界面模式」（手机版在「我的」中）可选择自动、手机 / 平板或 TV / 遥控器；选择保存在本机，切换后重建界面。电视保留全屏沉浸与遥控器焦点；手机、平板显示状态栏与导航栏，并按刘海、导航栏和输入法高度留出边距。输入法边距原地更新，不重建页面。普通页面跟随系统方向设置，主动全屏只在播放期间临时请求所选方向；播放页旋转保持同一个播放器。调试包的「关于果映 TV」显示测试构建标识及当前界面模式，正式版本号不因调试递增。

触屏设备使用四栏底部导航：首页、观看历史、排行榜、我的。收藏和账户预约从「我的」进入；观看历史直接进入原有本机／账户历史页。右上角「找剧」统一提供关键词搜索和分类筛选：进入即可看到搜索框及分类，搜索结果可返回分类，不再从「我的」进入独立筛选页。输入使用系统输入法。分类选项按宽度自动换行，文字水平、垂直居中；较长筛选区可上下滚动，也可收起以浏览结果。海报墙按可用宽度使用 3/4/6 列，四个榜单在手机上分两列完整展示，题材与刷新按钮另排一行；题材弹窗也采用两列并完整显示文字。普通按钮、卡片不再通过第一次触摸获取焦点，单击直接执行；TV 保留遥控器布局和焦点规则。

TV 与手机共用冷灰背景、白色卡片、柔和高光与投影按钮，深色外观也共用对应表面配色；由同一套本地 Drawable 绘制，不依赖模糊或额外动画。手机保留居中顶栏、圆形底部导航及触屏按下反馈。TV 使用顶部七栏目导航、电视布局和遥控器焦点链：当前栏目以橙色文字和浅色选中底区分，遥控器焦点增加清晰的 3dp 橙色描边，海报描边位于图片内边距外侧；橙色主操作获得焦点时还有白色内边。首页、筛选、榜单、设置、选集和应用弹窗统一使用共用表面；全屏视频区域仍使用黑底，控制层标题和进度说明保持浅色以确保可读。

手机紧凑布局（M17 调试包）：页头改为 52dp，底部圆形图标区域缩至 40dp，导航整项保持至少 56dp 点击高度；按钮缩小可见表面、字号、图标与内外间距，实际点击区域仍至少 48dp。首页、找剧筛选、榜单、历史、我的及播放操作区采用更紧凑的触屏尺寸，长标签和大字体可换行增高；冷灰、纸白与橙色样式及 TV 布局、遥控器焦点规则保持原有方案。此调试包不递增正式版本；手机实机视觉与官网登录、滑块闭环仍待用户安装验收。

手机顶部搜索图标与左侧分类共用扁平背景：未按下时没有凸起底板、边框或阴影，点击保留同样的波纹反馈。放大镜图标、48dp 点击范围、搜索与分类找剧入口保持原有行为。

登录、账号同步、确认提示、设置选择及更新等应用内弹窗统一跟随当前浅色／深色外观，保留系统字体和原有按钮行为；手机弹窗使用圆角卡片、柔和遮罩及同风格操作按钮。输入框、列表文字和选中标记按弹窗主题显示，避免浅色页面出现深灰窗口或浅色输入文字不可读。评论与弹幕设置面板使用对应卡片表面；系统安装器等系统窗口仍由 Android 管理。

M32 修复 TV 选项菜单只露出一行：按每一行的实际文字高度计算列表与窗口，解除系统内容容器的一行高度限制，标题和底部操作保留空间。账号三项操作、倍速、清晰度、外观、界面模式、画面模式和剧集快捷操作在可用屏幕内一次展开；定时停止的八项改为四列两行，网格末行可向下到返回按钮。云端观看记录、搜索历史等长列表超出可用高度时仍可滚动，滚动条常显；大字体也按实测高度决定是否需要滚动，不强行缩字。手机选项布局不变。API 23／26 自动化覆盖一行高度限制、完整可见、账号三项、选择回调、长列表末项与网格焦点；实际电视效果待安装验收。

M31 针对 TV 仍出现黑底深字的反馈补强基础弹窗：内容根节点也铺不透明主题底色，清理系统容器背景及 backgroundTint，覆盖没有标准面板名称的固件额外层级；布局后及每次绘制前重新校正，关闭后移除监听。应用自定义内容（包含二维码白底）和列表行／焦点 selector 不受背景清理影响。Android 10+ 主题与窗口视图禁用系统强制深色反色，继续由应用浅／深外观决定配色。API 23／26 回归通过注入额外黑底与染色、显示后重复改色来验证；API 29 覆盖系统夜间模式。未连接电视复现其固件，实际显示仍需安装验收。本地验收构建可用 `HONGGUOTV_BUILD_LABEL` 指定「设置 → 关于果映 TV」中的构建标识（仅字母、数字、点、横线、下划线，最多 80 字符），用于区分同版本号安装包；默认正式构建不显示此标识。

M26 对比度修复：扫码输入与其他共用提示弹窗使用不透明底板，防止窗口 drawable 缺少 enabled 状态时把卡片底色降为半透明，影响标题和说明。操作文字与题材选择使用适合底板的强调色，集数键盘聚焦时使用深色数字配橙底；遥控器焦点描边不变。排行榜名次浮层加深，普通名次固定白字、前三名保留橙字，避免浅色主题的深字叠在深底。Android 6／8 自动化覆盖浅／深色及手机／TV 弹窗配色，真实电视视觉仍待用户验收。

M28 补齐全局弹窗可读性：系统 AlertDialog 的标题、内容、自定义区与按钮区不再使用固件可能提供的独立深色底板；对话框主题显式指定浮层底色、正文、提示、链接和勾选颜色。账号菜单、扫码登录、同步提示、扫码输入、备份恢复、设置选择、更新、评论、弹幕设置与选集共用这条基础链路。首次显示后新增或复用的文字会在布局时校正配色，关闭窗口时移除监听；复选框单独处理，避免因继承 Button 而漏着色。自定义 Dialog 同样接入，卡片底板不再因缺少 enabled 状态降为半透明，实际禁用按钮仍保留反馈。官方扫码说明显式指定主题文字色，二维码黑白内容与登录、网络、预约及更新协议不变。自动化覆盖 API 23／26、两套主题、真实扫码登录样例和更新复选框等场景；未代为登录、安装或操作电视，实际显示仍待用户验收。

手机账号页提供「官方网页登录」入口，加载红果完整官网。使用 Windows 桌面浏览器标识，避免「Mac 标识 + 触摸屏」被官网识别为 iPad；官网加载完成后仅调整视口为 1280 宽度并允许双指缩放，通知官网重新计算桌面布局，避免手机窄屏隐藏登录按钮。官网布局加载后自动点击页头的「登录」入口（最多等待约 30 秒），页面首次可见即开始准备，不依赖所有第三方资源加载结束；只有实际检测到官网登录弹窗才结束等待，其他模态窗口不会被当作登录成功，尚未绑定事件时会限频重试。已弹出窗口时不重复点击；用户关掉弹窗后不会反复弹出，底部「打开登录」可手动重试。离开页面或关闭窗口会停止等待。不读取或提交网页表单、不勾选协议、不获取验证码，不改动官方验证逻辑。默认「手机登录」模式仅通过 CSS 将官网双栏重排为单栏短信表单，保留协议与原输入控件，隐藏扫码栏；协议行保留定位容器，并将官网原有透明复选框的 44px 点击区域对齐圆圈，协议链接可单独打开，仍需用户手动勾选；按照 WebView 可用宽高（含键盘弹出与横竖屏变化）显示，验证码窗口从验证容器中寻找官网无 id/class 的 iframe，只读取该 iframe 元素自身的几何来自动缩放和定位；仅有遮罩而 iframe 还不可见时显示加载提示，不改图片、滑块、跨域 iframe 内容或验证回调。仅在新窗口或可用尺寸变化时调整，手指操作过程中不抢占位置。未识别的验证组件仍需原网页备用工具，不能保证所有官网风控窗口都适配。右上角「原网页」可随时撤销适配 CSS，显示原生「缩小／放大／恢复全页／移动页面」工具：网页遮罩阻止拖动时，开启移动页面后可直接平移 WebView，移好后必须点「结束移动」才可操作滑块；恢复全页只改变缩放及滚动位置，不刷新官网或清除当前输入。验证窗口放大后的实际拖动体验仍待用户真机验收。登录窗口自动打开后，用户在网页内自行输入验证码并完成滑块，再点「完成登录」；客户端验证官网会话及账户接口后加密保存登录态，关闭页面会清理临时网页 Cookie 和存储。验证失败保留网页供重试，关闭或取消后的验证结果不接入账户。账号管理移除客户端直接发送短信的手机号加验证码入口和标题中的“测试功能”字样；手机只提供官方网页登录与另一台设备扫码，TV 只提供扫码。官网内仍由用户手动输入手机号、验证码并处理验证。未代填表单或自动处理验证码。已核验官网登录弹窗，真机滑块、设备 WebView 兼容性和账户登录闭环仍待用户测试，不能保证所有设备或风控场景成功。

手机首页的「推荐／漫剧／真人剧／换一批」固定在顶部栏，右侧保留放大镜搜索；内容可纵向滚动，依次显示首集试播、两行简介、常驻「观看全集 / 账户收藏」、上一部 / 下一部、继续观看及更多好剧。暂停按钮位于视频角落，也可直接点击画面暂停或继续；观看全集直接进入独立播放页，按本机记录续播。无本机记录时不显示继续观看，无其他作品时不显示推荐区域。手机播放页的图标与文字按整体居中；首页操作、筛选和选项弹窗的同行按钮等高。官网登录工具与操作按钮可随大字体增高；图标按钮保留 48dp 点击区域，长文案仍可换行。实际字体和网页登录场景仍待手机验收。

独立播放页在竖屏下显示顶栏、16:9 视频区与可滚动的信息区。上一集、选集、下一集、账户收藏、评论、弹幕设置及播放设置常驻；附近五集可直接点按，下方显示简介及服务端返回的相关作品。相关作品保留全部返回项和「第几季／同IP／待上线」等标记，当前剧集单独标示并默认定位上一季，横向滑动可浏览；若当前季无法与接口季标记对应则从列表开头显示。加载失败可重试，已上线作品可进入播放，待上线作品使用现有预约流程。预约跨设备结果仍需账号验收。「竖屏全屏」和「横屏全屏」分别请求相应方向并放大画面；视频控制层的全屏按钮在进入时使用竖屏，再次点击或按返回退出全屏，恢复进入前的方向策略和系统栏，再按返回回到来源页。切换方向复用当前播放器与视频视图，不重新解析剧集；视频默认保持原比例，可按个人设置调整画面模式。不同手机的旋转锁定、系统手势和实际播放连续性仍需用户验收。

选集使用底部面板，每 20 集分组，提供横向分组标签、跳转集数与五列集数按钮；点按集数立即播放并关闭面板，当前集高亮。旋转时原地调整面板，保留评论内容和选集分组；弹幕设置可纵向滚动。触屏控件保留至少 48dp 点击区域与按下反馈。

自动回归在 API 23/26 覆盖四栏导航、实际触摸单击回调、首页常驻操作、320dp 小屏与 1.3 倍字体、全屏/旋转复用视频视图、选集状态及键盘/安全区域边距更新。真实手机的字体、系统栏、输入法动画、手势返回与实际播放连续性仍需用户安装验收。

## 构建环境

需要 JDK 17、Android SDK Platform 36 和对应 Build Tools。设置 `JAVA_HOME`、`ANDROID_HOME`，或在本地 `local.properties` 配置 SDK 路径。可以用 Android Studio，或在支持 Android/Gradle 的 IDEA 中打开本目录；也可直接使用终端。

以下命令均从仓库根目录执行：

```sh
# 回归检查和开发 APK
./kotlin-tv/gradlew -p kotlin-tv :core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug

# 只生成开发 APK
./kotlin-tv/gradlew -p kotlin-tv :app:assembleDebug
```

默认产物：`kotlin-tv/app/build/outputs/apk/debug/app-debug.apk`。

## 版本与签名

调试时保持 `app/build.gradle.kts` 的 versionName/versionCode 不变，通过文件名区分测试包。环境变量 `HONGGUOTV_VERSION_CODE`、`HONGGUOTV_VERSION_NAME` 会覆盖文件中的默认值。此 fork 的正式版为 0.1.13（versionCode 54），后续正式发布再递增。分支名、APK 文件名或 Git 标签不会自动改变 APK 内部版本。

开发 APK 使用本机 Debug 签名。电视已经安装的版本只能由相同包名、相同签名的新版覆盖；换电脑或改用其他签名可能无法覆盖安装。不要删除、替换现有签名密钥，不要将密钥或密码提交到仓库。

Release 构建读取 `kotlin-tv/keystore.properties`（已忽略）或对应环境变量：

| 本地配置字段 | 环境变量 |
| --- | --- |
| storeFile | HONGGUOTV_KEYSTORE |
| storePassword | HONGGUOTV_STORE_PASSWORD |
| keyAlias | HONGGUOTV_KEY_ALIAS |
| keyPassword | HONGGUOTV_KEY_PASSWORD |

`storeFile` 建议填写已有密钥的绝对路径。默认 assembleDebug 使用本机 Debug 签名；交付测试包另用原签名签署并核验，不能只根据文件名判断签名。

## 正式发布与在线更新

从仓库根目录使用统一入口：

```sh
# 只读预演：核对两平台已发布版本、标签和草稿，输出版本规划
python3 scripts/release-tv.py

# 功能已验收并合入 main、工作区干净后，明确执行正式发布
python3 scripts/release-tv.py --publish
```

正常发布无需手动指定版本；自动执行版本提交/PR、构建检查、原签名与 v1 校验、双平台标签和附件发布及 Latest 核验。首次需要配置已有凭据、工具链和原签名；中断后按记录使用 `--publish --resume <版本>`，不另开版本。新包名过渡由更新说明明确提示单独安装，不将旧包当作新包覆盖升级。

`./scripts/build-kotlin.sh` 只做本地 Release 构建和配套清单生成，不发布。它按实际版本写入 `outputs/releases/<tag>/`；调试期间优先使用 assembleDebug，避免用相同版本覆盖本地保存的正式包目录。完整配置与故障恢复见 [AUTO_UPDATES.md](AUTO_UPDATES.md)。

用户后续在同包名果映 TV 内可从 GitCode 检查、下载并校验新版，由系统确认安装。GitHub/GitCode Release 也可手动下载；本地测试包没有上传正式渠道，不会被应用内更新获取。

## 验证边界

框架回归覆盖 API 23、API 26。具体电视的解码、声音、遥控器和实际账号同步仍需要设备验证。由维护者改代码、自动化检查和打包，用户安装测试并反馈截图；不自动操作用户模拟器。

竖屏与横屏视频都按设备解码能力选流：启动时探测 AVC/HEVC 解码器上限（logcat 搜索 `Decoder capabilities`），选流优先跳过盒子声明解不了的档位，并在播放前用 MP4 头里的实际编码尺寸复核，超出上限时自动沿清晰度阶梯降档（HUD 显示"自动降清"）。部分盒子会虚报解码能力（声明可解、实际失败）：此类运行时失败会按"编码+编码尺寸"记入持久化的设备能力记录（跨重启、跨剧集生效，竖屏失败不影响横屏），并当场自动降档重试（每集至多 2 次，无需手动切换），logcat 出现 `Learned decoder failure` / `Auto downgrading`。全部档位都不可解时保持原"兼容资源"行为交由系统尝试；播放失败面板的"尝试 xP"只在确有更低档位时出现；"播放设置 → 重置设备能力记录"可清除学习结果（应对盒子固件升级）。

播放中持续监测视频帧处理偏移（logcat 搜索 `Video frame offset` / `Resync after audio/video drift`）：平均偏移持续超过 150ms 时自动对当前位置做一次无感重同步（间隔至少 30 秒），用于消除随播放时长累积、倍速下更快的音画不同步。
