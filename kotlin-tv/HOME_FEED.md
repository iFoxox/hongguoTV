# 首页推荐与试播

首页加载与换剧优化已经用户验收，并在 TV `0.1.7` / versionCode 48 正式发布，支持 Android 6+。当前更名、新包名、图标与遥控器搜索属于后续本地改动，尚未正式发布。

## 内容来源

默认「推荐」读取官方 App 域名下 `/reading/bookapi/bookmall/tab/v1/`，tab_type=16、bottom_tab_type=7；与官网固定分类列表分开。路径及卡片结构参考 [guoapp 公开实现](https://github.com/Xanerix/guoapp/blob/main/native/core/provider_hongguo_recommendations.go)，请求与解析在本项目独立实现。真人剧、漫剧按钮读取官方 App `/reading/distribution/category/landpage/v/` 分类推荐，分别使用 short_play/default 与 comic_series/comic_series，排序条件留空，支持服务器会话、offset、filter_ids。找剧页面使用独立的组合分类筛选。

推荐卡片可能包含全剧分集信息。客户端优先试播第一集，遇到该集没有可解码清晰度时依次尝试第二、三集，并标注实际集号。

客户端采用服务端分页会话和偏移量，默认推荐按服务端实际下发的条数推进。按账号和来源在本机保存分页会话、偏移量和有限的去重记录，冷启动可从上次的推荐批次继续。请求完成但页面丢弃结果时，同一页重试复用内存中的结果。「换一批」通常继续后续批次；连续三批重复后可再次点「换一批」重置当前来源，可能重新出现旧作品。进入详情后返回会恢复列表与试播位置。

登录且账号验证通过时，向推荐域名发送账号 Cookie，查询参数省略登录设备 ID 和安装 ID。启动先恢复账号身份，再启用对应的续刷缓存。临时匿名浏览不会清除尚未验证的账号的续刷记录。模拟账号请求已覆盖隔离行为，真实账号续刷仍待实机验证。

三种首页来源共用备用域名顺序 `api5-normal-sinfonlinea.fqnovel.com` → `api5-normal-hl.fqnovel.com` → `api5-normal-lf.fqnovel.com`。收到错误码 110，或已有分页会话时收到服务端正数错误码，会清除会话和偏移量后尝试下一域名，继续过滤已展示作品。每次分页最多请求三次，耗尽时保留服务端错误提示。登录请求仍禁止重定向。

## 遥控器与播放

当前工作区首页已采用用户选定的 B 方案：七项菜单在顶部，左侧三列可滚动海报，右侧固定试播与信息。海报焦点移动只更新信息，浏览其他作品时暂停旧试播、展示新封面，确认后切换试播；右侧「观看全集」「账户收藏」作用于正在浏览的作品。初次进入仍试播首部作品；右侧画面继续保留上下换剧快捷键。返回先从预览区回到海报墙，再回顶栏。「更多作品」追加来源列表；继续观看入口在有本机记录时提供记录选择。海报浏览标识与试播索引分开保存，切换来源、详情返回时恢复。以下缓存、首集与账号边界继续适用；实际电视观看距离和遥控器体验待用户验收。

首页试播和全集播放共用进程内的匿名播放设备会话，注册返回设备 ID、安装 ID 和设备 Cookie。播放模型优先请求签名 video_tab GET，再回退到签名的批量 POST。连续两轮换路全部返回空响应后，下一轮可重新注册一次匿名设备。注册失败与模型空响应分别提示。全档 bytevc2 的旧版模型最多额外尝试一次兼容编码请求。

用户主动试播遇到空响应时最多再尝试两轮，换新身份后也会先请求 video_tab。相邻作品的后台预加载只执行一轮。

旧播放接口的有界重试全部返回空正文时，客户端会在 `lf` 域名再请求一次签名 video_tab，再决定是否报告空响应。首页试播和全集播放共用这条路径。

2026-11-11 同步上游播放模型签名修复。首选、旧版和备用域名的请求均使用同一套新签名，签名时间与请求中的 `_rticket` 同源。

- 顶部有推荐、漫剧、真人剧、换一批，当前来源高亮；三类入口均续取后续推荐。
- 视频区上下切换作品，确定聚焦常驻的暂停、观看全集、账户收藏操作栏；预览区返回海报墙后，再返回顶部导航。
- 按比例显示画面，不裁切竖屏内容。准备好后收起底部状态提示，暂停、加载及错误时显示。
- 当前视频播放且缓冲达到 1.5 秒后，串行准备后面 3 部作品的播放地址及完整索引（先消费 32 KiB 并按需补齐完整索引，不等待整个 256 KiB 范围响应），保留上一部供回滑；相邻作品不足时提前补下一批卡片。缓存约 90 秒过期。
- 使用 Media3 DefaultPreloadManager 提前准备媒体源：下一部加载约 1.5 秒媒体样本，上一部加载约 1 秒，后两部提前选择轨道；共用一个 ExoPlayer 及其兼容组件，预加载总缓冲目标为 4 MiB。地址与索引就绪后即交给 Media3，不等待额外固定 1 MiB 预下载。换剧命中时将已准备的媒体源交给同一播放器并 prepare，不需要重新解析地址；仍可能有解码器切换等待，不保证所有电视与格式都无停顿。
- 若切到正在预加载的下一部，直接接续该任务，失败后再走前台请求；不会主动取消后立刻重复请求同一作品。切换其他作品或来源仍丢弃过期结果。
- 视频 HTTP 分段保持 512 KiB，但按实际收到的数据渐进读取和按绝对偏移解密，不等待完整分段下载；缓存包含完整已取 MP4 索引，避免大索引被播放器重复读取。
- 试播队列设置每个媒体末尾暂停，不自动跳下一部。再播、换剧或观看全集均由用户操作。
- 视频源移出预加载窗口后释放缓存；切换类型、退出、账号变化时清理旧源。HTTPS 连接池在后台关闭，避免界面线程网络异常。
- 试播没有 Library 保存和账户进度上传依赖；进入正式全集后才记录观看历史。推荐列表不进入收藏或历史数据库。
- 正常分类分页保留最多 72 部近期作品；缓存至多当前、上一部、后面三部。播放器缓冲目标约 6 MB。首页期间暂停自动更新检查。

## 首次进入与首集准备

- 首屏元数据缓存按登录身份隔离、10 分钟过期，每个来源最多 30 部。只保存卡片和已核验的首集 ID、集数。续刷快照另存分页会话、偏移量和去重记录。两者均不保存账号 Cookie 或播放 URL。
- 冷启动优先恢复有效续刷快照。没有续刷进度时可先试播缓存首屏，下一页再建立新的服务端分页会话并去重。
- 直接解析播放模型 video_list 数组中的 video_meta 与 encrypt_info，验证 URL、视频尺寸、编码和内容密钥；有可用项时省去 fallback_api GET，没有时保留原备用流程。匿名探针已交叉核对内嵌密钥与原备用响应一致，未打印地址或密钥。
- 首页索引准备在一次 256 KiB 分段响应中先消费 32 KiB，按索引实际大小继续读；不会为 32 KiB 以外、仍在本范围内的索引另开请求。超出范围时才补取，保留完整头、范围及样本校验。首次进入仍需实际推荐及播放信息；分类响应中的 episode 为布尔值，不能当首集序号，仍需可靠标识或详情核验。
- 匿名复测确认推荐及漫剧试播各使用 1 次播放模型请求、0 次备用接口请求，均成功准备视频索引。网络波动明显，探针不包含设备解码和首帧显示，不能作为电视端耗时保证。

## 验证

标准 core/app 单元测试、assembleDebug、lintDebug；页面测试覆盖 API 23、26。覆盖推荐卡片解析、分页重试与换批、账号请求隔离、来源切换、上下换剧复用预加载、下载中途切换及失败回退、慢速分段渐进读取、缓存与网络边界、实际 Media3 组件的注册/切换/清理、暂停/恢复和结束停留。接口替身及 Robolectric 不验证真实解码性能。

用户实机验收：默认推荐内容、换一批、漫剧/真人剧切换，停留几秒后上下换剧是否更快，试播结束是否停留，观看全集后返回位置，退出登录再登录是否更新内容，原有正式播放和云端进度是否正常。

版本码 39 修复共用 HTTP 客户端关闭跳转造成的内容请求 301：公开详情和视频允许跳转；推荐账号请求使用单独配置、禁止跳转的客户端，避免凭证转发。已实测两类推荐的后续批次、剧集详情、播放地址及 RemoteVideo.prepare，未操作模拟器或电视。

版本码 40 复用推荐响应中明确的 first_vid 或 video_list 中 vid_index=1 的标识及总集数，试播无需再请求一次详情；不使用未标记首集的普通 vid 代替。缺少可靠标识时回退完整详情，正式观看全集仍独立读取完整分集。试播专用 TrialClip 保存真实总集数，避免只取首集时误显示共1集。匿名探针将首集标识、总集数与官网完整详情交叉核对；分类推荐目前未提供这些标识，保留原详情流程。

公开内容客户端共享至多3条、空闲2分钟的连接池，各页面仍使用独立 dispatcher，关闭旧页面只取消其自己的请求，不误取消新页请求；账号推荐仍禁止跳转。此优化减少后续访问连接开销，首次进入仍受网络及播放解析耗时影响。

本轮只静态读取用户提供的官方 6.5.5.32 APK，确认存在 TTVideoEngine、DataLoaderHelper、短视频预加载准备与时机配置；没有运行官方包，也无法从组件存在推断其线上参数。播放器预加载按 [Media3 官方文档](https://developer.android.com/media/media3/exoplayer/preloading-media/preloadmanager) 独立实现。未进行官方与 TV 客户端的设备测速。`Home first-frame` 日志仅统计媒体源交给播放器至首帧的耗时，不包含先前推荐或播放地址请求。
